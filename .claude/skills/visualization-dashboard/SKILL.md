# Visualization Dashboard Skill

## B.1 Trigger and Contract

Invoke this skill whenever the user asks for a **dashboard**, a **results page**,
an **HTML report**, or a summary of a figure batch — and **automatically after
every figure batch** produced under the `algorithmic-art-academic` skill (Track F).

Hard rules:

- Output is **always** `report/index.html`.
- It is **regenerated idempotently from `report/manifest.json`**. Running the
  generator twice on the same manifest produces byte-identical HTML except for
  the generation timestamp.
- **Never hand-edit `index.html`.** Every change goes into the template inside
  `report/build_dashboard.py`. If the user asks for a visual tweak, edit the
  generator and re-run it.
- **Never require a build step.** No npm, no bundler, no Node. The page is one
  HTML file plus relative asset paths.
- Validate the manifest against the schema (Section B.5) **before** building.
  A malformed manifest is a hard failure, not a silent skip.

## B.2 Stack

- **Single self-contained HTML file.** Assets (PNG, SVG, GIF, interactive HTML)
  are referenced by **relative path only** — never inlined, never absolute, never
  `file://`.
- **Tailwind CSS** via the Play CDN: `https://cdn.tailwindcss.com`.
- **DaisyUI** via CDN stylesheet, with a **custom dark theme** declared through
  `daisyui.themes` in the Tailwind config block (or via CSS variables when the
  DaisyUI build in use does not expose the plugin config).
- **Lucide icons** via the CDN `lucide` script, activated with
  `lucide.createIcons()` after DOM content loads and again after any dynamic
  insertion. **`createIcons()` replaces each `<i data-lucide="name">` with an
  `<svg class="lucide lucide-name">`, discarding the placeholder's own
  attributes** — so size icons through `.lucide` (scoped per context), never
  through an `i` element selector, which stops matching the moment the icons
  render. Guard the call in a `try`/`catch`: an icon name absent from the pinned
  version must not break the page.
- **Inter** from Google Fonts for text, **JetBrains Mono** for numbers.
- **Plotly.js from CDN** is available for interactive embeds; any variant with an
  `html` entry, and any `animation.html`, is embedded **via an `<iframe>`** so the
  exported Plotly page keeps its own scripts and cannot collide with the
  dashboard's.
- **Vanilla JavaScript only.** No React, no shadcn, no npm, no framework.

CDN pins to use (update only with a reason):

```html
<script src="https://cdn.tailwindcss.com"></script>
<link href="https://cdn.jsdelivr.net/npm/daisyui@4.12.14/dist/full.min.css" rel="stylesheet" type="text/css" />
<script src="https://cdn.jsdelivr.net/npm/lucide@0.454.0/dist/umd/lucide.min.js"></script>
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&family=JetBrains+Mono:wght@400;500&display=swap" rel="stylesheet">
```

## B.3 Layout and Behavior

### Theme

Minimalist dark. These are the exact values:

| Role       | Hex       |
|------------|-----------|
| Background | `#0B0F14` |
| Surface    | `#111827` |
| Border     | `#1F2937` |
| Text       | `#E5E7EB` |
| Muted      | `#9CA3AF` |
| Accent     | `#2563EB` (the academic palette blue) |

Generous whitespace on an **8 px spacing scale** (`p-2 p-4 p-6 p-8`, gaps in
multiples of 8). **Max content width 1280 px** (`max-w-[1280px] mx-auto`).

The dashboard chrome is dark. **The figures themselves are not.** Every paper
figure is displayed **as is**, on a light card inset (`#FFFFFF` or `#F8F9FA`)
with modest padding, so the white-background figure reads correctly and is never
inverted, tinted, or filtered.

### Structure

- **Sticky left sidebar**, 260–280 px wide, collapsing to a top bar below
  1024 px. It lists each `group_title` as an anchor link with a **Lucide icon per
  group**, and highlights the active section on scroll (IntersectionObserver on
  the section headings, not a scroll-position calculation).
- **Header** with the project name, the run date, and a compact stats row built
  from the DaisyUI `stat` component: number of figures, number of groups, number
  of distinct seeds.
- **One `<section>` per group**, in order of first appearance in the manifest.
  Inside each, a responsive **bento grid** of DaisyUI `card` components. Use
  `grid-template-columns: repeat(auto-fit, minmax(min(420px, 100%), 1fr))` rather
  than fixed breakpoint column counts: the row fills whatever the figure count,
  the `min(..., 100%)` keeps it from overflowing a 390 px viewport, and the 420 px
  floor keeps the embedded paper figure legible. A wide-span class stays
  available for figures that deserve the full row.
- **Each card** holds: the figure image on the light inset, the short `caption`,
  and a **metrics chip row** rendered in JetBrains Mono. Display the variant's
  **SVG when present** and fall back to its PNG; both stay available from the
  download buttons. Clicking the figure opens it full size in the modal.
  (Verification requires `naturalWidth > 0` on every `<img>`, which catches an
  SVG exported without intrinsic `width`/`height` attributes — if that ever
  fires, the fix is the export, not switching the card to PNG.)
- **Variant switcher.** When a figure has more than one variant, render a
  segmented control above the image — a DaisyUI `join` of buttons — that switches
  the displayed variant with a **200 ms crossfade**. It must be **keyboard
  accessible**: real `<button>` elements, `role="tablist"` / `role="tab"`,
  `aria-selected`, arrow-key navigation, visible focus ring.
- **Animation controls.** When `animation.gif` exists, add a **play button** that
  swaps the static image for the GIF (and back). When `animation.html` exists,
  add an **"Interactive"** button that opens the Plotly HTML in a DaisyUI `modal`
  containing an `<iframe>`.
- **Info popover.** Every card carries an info button (Lucide `info`). **Hover
  opens it; click pins it** (pinned stays open until dismissed by click, `Esc`,
  or an outside click). It shows the full `details` rendered from Markdown, plus
  `seed`, `dataset`, `model`, and links to the underlying files.
- **Download buttons** for PNG and SVG on each card, using the `download`
  attribute and the relative path.
- **Entrance animation.** Scroll-triggered fade-and-rise on cards via
  IntersectionObserver, 300 ms ease-out, staggered slightly within a row.
  **Disabled entirely when `prefers-reduced-motion: reduce` is set** — cards then
  render immediately at full opacity.
- **Search box** in the sidebar filtering cards live by `title`, `caption`, or
  group. Empty groups hide themselves while a filter is active, and a "no
  results" state appears when nothing matches.
- **Footer** with the generation timestamp and the manifest path.

### Accessibility and robustness

- Every `<img>` has meaningful `alt` text (the figure title).
- Focus is visible on every interactive control.
- The page must render **without horizontal overflow at 390 px, 768 px, and
  1440 px**.
- A missing asset must degrade to a visible placeholder in the card, not a broken
  layout — but it is still a **verification failure** (Section D).

## B.4 Generator: `report/build_dashboard.py`

Pure Python, **standard library only**, plus `markdown` when importable with a
plain-text fallback when it is not. Type hints and docstrings on every function.

Responsibilities, in order:

1. Load `report/manifest.json`.
2. **Validate** every entry against the schema in B.5. Collect all errors, then
   raise once with the full list. Do not build from an invalid manifest.
3. Group entries by `group`, **ordering groups by first appearance** and keeping
   within-group order as written.
4. Assign a Lucide icon per group (a small keyword map with a stable fallback
   such as `chart-line`, cycling deterministically so the same group always gets
   the same icon).
5. Render `report/index.html` from a template **embedded in the script**.
6. Print a one-line summary: figure count, group count, output path.

**Render every card server-side in Python.** The page's JavaScript only handles
interaction, never construction. Per-figure state that the JS needs (the variant
list, the search blob) rides on the card element as `data-` attributes holding
HTML-escaped JSON. This keeps the Tailwind Play CDN from having to scan
dynamically inserted markup, and it means the page still shows every figure with
JavaScript disabled. HTML-escape every string that lands in markup.

Interface:

```bash
python report/build_dashboard.py [--manifest report/manifest.json] [--out report/index.html]
```

Exit non-zero on any validation or write failure.

## B.5 Manifest Schema (validated before every build)

Mirrors Section A.5 of `algorithmic-art-academic`. The manifest is either a JSON
array of figure entries, or an object `{"project": str, "run_date": str,
"figures": [...]}`.

Per entry:

| Field | Type | Required |
|-------|------|----------|
| `id` | non-empty string, unique | yes |
| `group` | non-empty string | yes |
| `group_title` | non-empty string | yes |
| `title` | non-empty string | yes |
| `caption` | string, ≤ 160 chars | yes |
| `details` | string (Markdown allowed) | yes |
| `seed` | int or null | no |
| `dataset` | string or null | no |
| `model` | string or null | no |
| `variants` | non-empty list of `{label, png, svg, html}` | yes |
| `animation` | null, or `{gif?, html?}` | no |
| `metrics` | list of `{name, value, unit}` | no |
| `created` | ISO 8601 string | yes |

All asset paths are **relative to `report/`**.

## B.6 Verification: `report/verify_dashboard.py`

Playwright-based. Install `playwright` with pip and the Chromium browser with
`python -m playwright install chromium` if absent. The script **fails loudly**
(non-zero exit, explicit failure list) on any of:

- `index.html` loads with **zero console errors** and **zero failed network
  requests for local assets** (CDN failures are reported separately as warnings,
  since they depend on network availability).
- **Every image path in the manifest resolves to an existing non-empty file**,
  and **every `<img>` on the page has `naturalWidth > 0`**.
- **Every variant switch button changes the displayed image** (click each, assert
  the visible `src` changed).
- **Every info popover opens** (click each info button, assert the popover
  becomes visible).
- The page renders **without horizontal overflow** at **390 px, 768 px, and
  1440 px** widths (`scrollWidth <= clientWidth + 1`).
- A screenshot of the full page at 1440 px is saved to
  `report/verification/dashboard.png`.

The manifest is validated against B.5 **before** the browser is launched.

```bash
python report/verify_dashboard.py [--report-dir report] [--no-screenshot]
```

## B.7 Workflow

```bash
# after any figure batch
python report/build_dashboard.py
python report/verify_dashboard.py
```

If verification fails, **fix the cause and rerun before reporting anything to the
user**. Never report a dashboard as done on the strength of the build step alone.

Report tersely: figure count, group names, the dashboard path, the screenshot
path. Do not describe the figures at length.

## B.8 What Not to Do

- Do not hand-edit `report/index.html`.
- Do not inline base64 assets; keep relative paths.
- Do not introduce npm, a bundler, React, or shadcn.
- Do not copy code from design showcase sites — implement the look from this
  description.
- Do not invert, tint, or filter the paper figures to match the dark theme.
- Do not add motivational commentary to generator output or agent reports.
